# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Решение

### Инструкция по запуску

Нужен Node.js 20 или новее (`node --version`). Устанавливать зависимости не нужно.

1. Перейдите в каталог проекта:
   ```sh
   cd neowise-candidate-triage-starter
   ```
2. Запустите сервер:
   ```sh
   npm start
   ```
   Без npm: `node server.mjs`. Другой порт: `PORT=8080 npm start`.
3. Откройте http://127.0.0.1:3000, введите текст заявки и нажмите «Разобрать заявку».
4. Сценарии сбоя проверяются метками в тексте заявки: `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Например, с текстом `Где мой заказ? [timeout]` страница покажет сообщение о ручном разборе, а черновика не будет.
5. Остановка сервера: `Ctrl+C`.

Проверка API без браузера:
```sh
curl -s -H 'Content-Type: application/json' -d '{"text":"Когда доставка?"}' http://127.0.0.1:3000/api/triage
```

### Инструкция по запуску тестов

Сервер для тестов запускать не надо: тесты сами поднимают его на свободном порту и потом останавливают.

```sh
npm test
```

Без npm: `node --test test/triage.test.mjs`.

Ожидаемый результат в конце вывода: `# pass 14` и `# fail 0`. Если хотя бы один тест упал, команда завершится с ненулевым кодом.

Что проверяют тесты (`test/triage.test.mjs`, встроенный `node:test`):
- корректная заявка → `200 ready` с темой и непустым черновиком;
- битый JSON, нет `text`, `text` не строка, пустая строка или одни пробелы → `400 invalid_input`;
- `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` → `200 manual_review`;
- `[timeout]` → `200 manual_review`, ответ быстрее 800 мс (лимит модели 300 мс);
- модель, которая игнорирует сигнал отмены, тоже обрывается по таймауту;
- ответ модели не объект (массив, `null`, строка) или в нём нет черновика → `manual_review`.

### Где проверяется результат AI

`parseModelOutput()` в `server.mjs`: ответ модели должен быть JSON-объектом, `topic` — одно из `delivery | pricing | other`, `draft` — непустая строка (после `trim`). Всё остальное — `manual_review`.

### Что происходит при сбое

- Вызов модели ограничен 300 мс (`callModel`): `AbortController` + гонка с таймером, поэтому лимит соблюдается, даже если провайдер не реагирует на сигнал.
- Таймаут, исключение модели или ответ, не прошедший проверку → HTTP 200 `{"status":"manual_review","topic":null,"draft":null}`.
- Страница перед каждым запросом очищает прошлую тему и черновик; при `manual_review`, ошибке сети или неожиданном ответе показывает сообщение «разберите вручную», черновика на экране нет. Ответы на устаревшие запросы (двойной клик) игнорируются.

### Решения, которые стоит обсудить

- Строка из одних пробелов считается пустым вводом (400).
- Тело больше 64 КБ тоже даёт 400 `invalid_input`.
- Черновик показывается в редактируемом поле: менеджер правит текст перед отправкой.

### Польза для менеджера

Менеджер получает готовые тему и черновик за доли секунды, а при сбое AI сразу видит, что заявку надо разобрать вручную, и не отправит клиенту устаревший черновик от прошлой заявки. Измерить можно по среднему времени от поступления заявки до первого ответа клиенту и по доле черновиков, отправленных без серьёзных правок.
